# Stock Value Lens search keywords and LLM questions

Reviewed: **2026-10-21**. Website: [Stock Value Lens](https://stockvaluelens.com/). Audience assumption: English-speaking users researching US-listed stocks. This is a qualitative priority list, not investment advice.

## Ranking notes

Each page type has two separate lists because they are intended for different tools:

- **Search keywords** are short phrases for keyword research tools such as Keyword Planner.
- **LLM questions** are natural-language prompts for testing discovery and answers in assistants.

Ranks are estimated likelihoods within each list, based on common investor tasks, query breadth, page fit, and current site content. Each row also has a content rating: **2 — strong** means the page directly covers the term or answers the question; **1 — partial** means coverage is incomplete, conditional, or indirect; **0 — weak** means the page does not answer it or the content is missing. Keyword ratings assess topical fit to the specific page, not exact-match wording. No keyword-volume data or Search Console export was available, so likelihood ranks are hypotheses rather than measured demand, traffic forecasts, or organic-difficulty scores. Company-page lists use `[TICKER]` and `[COMPANY]` placeholders; substitute the specific company and only its supported metrics. Demand varies by country and over time.

## Overall page-type search potential

This cross-site order estimates total discovery potential, separate from the within-page rankings above:

1. **Company financial-history pages** — many ticker-specific pages can match long-tail EPS, P/E, cash-flow, and historical-financial searches.
2. **Stock-tool comparison pages** — brand-versus-brand and alternative searches are specific, high-intent queries; the overview and 11 reviews directly target them.
3. **Homepage and chart tool** — broad stock-chart and research terms may have high demand, with strong competition.
4. **Stock directory** — helps users find the right company page and can match ticker lookup searches.
5. **P/E, price-versus-earnings, and CSV guides** — common historical research tasks with clear intent.
6. **Head-to-head comparison tool** — useful for company comparisons, though some users seek live performance or recommendations instead.
7. **Other metric guides** — narrower educational topics such as EPS versus FCF, margins, and dividend yield.
8. **AI/data resources and catalog** — high fit for programmatic use, but a specialized audience.
9. **Methodology and sources** — valuable for trust and interpretation, with lower expected query volume.
10. **Overview-only company pages** — can match business-profile searches but do not provide historical financial charts.
11. **Updates, about, and privacy pages** — mostly brand, navigational, or trust searches.

The overall order remains a hypothesis. Validate keyword phrases by country and language with Keyword Planner or a comparable volume source. Review LLM prompts separately in the assistants you care about; search rankings and assistant discovery measure different behavior.

## Recommended content and metadata scheme

This proposal uses the query ratings above to improve how well each page answers a likely search or assistant question while keeping the copy useful to people who arrive on the page. The competitor comparison overview and individual provider comparison pages are excluded, as requested. Recommendations below cover page templates and content rather than implementing site changes.

### Shared rules for every page type

- Give each URL one clear job. Put a direct, natural answer or orientation near the top of the page, then let the chart, table, or tool remain the main experience.
- Use the page's actual data to generate company-page copy and metadata. Name only metrics that are available on that page; show missing data plainly. Never imply a current quote, forward estimate, recommendation, or fair value when the page contains historical inputs.
- Keep the title, meta description, H1, opening copy, and page content aligned. Write readable summaries rather than strings of keyword variants. Use a distinct title and description for every indexable HTML URL.
- Keep date meanings separate: latest price date, latest fiscal period, financial-data cutoff, and any directory or index snapshot date. Include the relevant one where it helps the user judge freshness.
- Match structured data to visible content. Use WebPage for tools and reference pages and Article for editorial guides. Do not add ratings, offers, or FAQ schema unless those facts and answers are visible and accurate. Set a self-referencing canonical URL and matching Open Graph title, description, and URL.
- Treat raw JSON and text resources as machine-readable data, not as HTML pages needing meta tags. Give them stable field names, source and cutoff dates, units/currency, a schema version, and explicit nulls for unavailable values so missing data cannot be mistaken for zero.
